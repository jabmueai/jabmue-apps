# เบื้องหลัง: แอป "รถมาหรือยัง" สร้างอย่างไร

สรุปไว้สำหรับทำคลิปอธิบาย · เว็บจริง: https://jabmue-bus.vercel.app · คู่มือ: [/help](https://jabmue-bus.vercel.app/help)

## 1. โจทย์

ผู้ชมคลิปขอ: คนต่างจังหวัดยืนรอรถเมล์/สองแถวริมถนน **ไม่รู้ว่ารถจะมาเมื่อไหร่**
ไอเดียคือให้มือถือคนขับส่ง GPS → จับกับแผนที่ OpenStreetMap → ผู้โดยสารเห็นว่ารถอยู่ไหน อีกกี่นาทีถึง

## 2. ใช้ AI ตัวไหน ทำงานอย่างไร

ใช้ **Claude Code** (AI ที่ทำงานเป็น "เอเจนต์" ไม่ใช่แค่ตอบแชท) ต่างจากแอปอื่นในช่องที่ใช้ Gemini Canvas เขียนไฟล์เดียว:

| Gemini Canvas (แอปก่อน ๆ) | Claude Code (แอปนี้) |
|---|---|
| เขียน HTML ไฟล์เดียว | เขียนหลายไฟล์ ทั้งหน้าเว็บและเซิร์ฟเวอร์ |
| ข้อมูลอยู่ในเครื่องคนใช้ | มีเซิร์ฟเวอร์กลาง ให้หลายคนเห็นข้อมูลเดียวกันสด ๆ |
| เราลองกดเอง | AI เปิดเบราว์เซอร์จำลองมือถือ กดทดสอบเอง ถ่ายรูปหน้าจอดูเอง |
| เรา copy โค้ดไปวาง | AI commit + เปิด Pull Request + merge ขึ้น GitHub → Vercel deploy อัตโนมัติ |

prompt ที่ใช้จริง 3 รอบ อยู่ใน [prompt.txt](prompt.txt) (มีฉบับรวบยอดให้คนดูลองเองด้วย)

## 3. ขั้นตอนที่เกิดขึ้น (ไทม์ไลน์ สำหรับเล่าในคลิป)

1. **วางคำขอผู้ชม + บอกว่า "deploy Vercel, มี 3 role, ใช้ง่ายสำหรับคนต่างจังหวัด"**
2. AI ออกแบบระบบเอง: เลือกเว็บแอป (ไม่ต้องโหลดจาก Store), ฐานข้อมูล Redis, แผนที่ OSM
3. AI เขียนโค้ด → เปิดเซิร์ฟเวอร์ทดสอบในเครื่อง → **จำลองมือถือ 3 เครื่อง** (แอดมินปักป้าย, คนขับขยับ GPS, ผู้โดยสารดูเวลา)
4. เจอบั๊กเอง: คนขับขยับแล้วตำแหน่งไม่ส่ง → แก้ → ทดสอบผ่าน
5. Push ขึ้น GitHub ไม่ได้ (สิทธิ์ผิดบัญชี) → AI วิเคราะห์ว่าบัญชีที่เชื่อมคนละบัญชี บอกวิธีแก้ → push ได้ → เปิด PR
6. เรา deploy บน Vercel → **ใช้จริงแล้วแผนที่ไม่โหลด ค้นหาไม่ได้** (เน็ต/VPN บล็อกเว็บแผนที่)
7. AI ทดสอบเว็บจริง → แก้ให้ทนทาน (เก็บไฟล์แผนที่เอง, สลับเซิร์ฟเวอร์ภาพแผนที่สำรอง, ค้นหาผ่านเซิร์ฟเวอร์เรา) → **เขียนชุดทดสอบ 54 ข้อ** → ผ่าน 54/54 บนเว็บจริง → merge → deploy
8. AI ถ่ายรูปหน้าจอจริง 18 รูป ทำ **หน้าวิธีใช้** แยก ผู้โดยสาร / คนขับ / ผู้ดูแล + FAQ

## 4. Architecture (โครงสร้างระบบ)

```
  📱 คนขับ (/driver)            📱 ผู้โดยสาร (/)              💻 ผู้ดูแล (/admin)
  GPS ทุก ~10 วิ                 ดึงตำแหน่งรถทุก 10 วิ          ตั้งสาย ป้าย คนขับ
        │  POST ping                    │  GET live                   │  POST save-config
        ▼                               ▼                             ▼
  ┌──────────────────────── Vercel ───────────────────────────────────────────┐
  │  หน้าเว็บ (HTML/CSS/JS ไม่ต้อง build) + CDN cache 4 วิ ลดโหลด              │
  │  Vercel Function: /api/bus  (ไฟล์เดียว รวมทุกคำสั่ง)                       │
  │    ├─ ตรวจรหัส (scrypt) / session / กันเดารหัส                             │
  │    ├─ ค้นหาสถานที่ → Nominatim (สำรอง Photon)                              │
  │    └─ เส้นตามถนน → OSRM                                                    │
  └───────────────┬───────────────────────────────────────────────────────────┘
                  ▼
        🗄️ Upstash Redis (ฟรี ผ่าน Vercel Storage)
          config = สาย ป้าย เวลา คนขับ   ·   live = ตำแหน่งล่าสุดของรถแต่ละคัน
                                                                     
  🗺️ ภาพแผนที่: OpenStreetMap (สำรอง CARTO) แสดงด้วย Leaflet
```

### ชิ้นส่วนที่ใช้

| ส่วน | ใช้อะไร | ทำไม |
|---|---|---|
| หน้าเว็บ | HTML + CSS + JavaScript ล้วน | ไม่ต้อง build ง่าย แก้ง่าย โหลดเร็วบนเน็ตต่างจังหวัด |
| ติดตั้งเป็นแอป | PWA (manifest + service worker) | กดเพิ่มลงหน้าจอได้ ไม่ต้องผ่าน App Store |
| แผนที่ | Leaflet + OpenStreetMap (สำรอง CARTO) | ฟรี ไม่ต้องมี API key |
| เส้นทางตามถนน | OSRM (ข้อมูล OSM) | ลากเส้นระหว่างป้ายตามถนนจริง คำนวณระยะแม่นขึ้น |
| ค้นหาหมู่บ้าน | Nominatim (สำรอง Photon) | ฟรี รองรับชื่อภาษาไทย |
| เซิร์ฟเวอร์ | Vercel Functions (Node.js) | ฟรี deploy อัตโนมัติเมื่อแก้โค้ดใน GitHub |
| ฐานข้อมูล | Upstash Redis | ฟรี เร็ว เหมาะกับข้อมูลตำแหน่งที่เปลี่ยนตลอด |
| ทดสอบ | Playwright (เบราว์เซอร์จำลอง iPhone) | AI กดทดสอบเองครบทุกบทบาท 54 ข้อ |
| เก็บโค้ด | GitHub + Pull Request | ทุกการแก้มีประวัติ ย้อนกลับได้ |

## 5. หัวใจของระบบ: คำนวณ "อีกกี่นาที" อย่างไร

1. ผู้ดูแลปักป้ายตามลำดับ → ได้ **เส้นทางตามถนน** (ชุดพิกัดต่อกัน)
2. ระบบรู้ว่าแต่ละป้ายอยู่ "กิโลเมตรที่เท่าไหร่" นับจากต้นสาย
3. ตำแหน่ง GPS ของรถ → หาจุดบนเส้นทางที่ใกล้ที่สุด → รถอยู่ "กิโลเมตรที่เท่าไหร่"
4. **ระยะที่เหลือ = ตำแหน่งป้าย − ตำแหน่งรถ** (ตามทิศที่รถวิ่ง)
5. **เวลา = ระยะที่เหลือ ÷ ความเร็วเฉลี่ย** (ผู้ดูแลตั้ง 20/30/45/60 กม./ชม.)
6. ถ้ารถผ่านป้ายไปแล้ว → คิดระยะไปถึงปลายสายแล้ววนกลับ + เวลากลับรถ 5 นาที
7. ทิศทาง: ถ้ารถวิ่งย้อนเกิน 400 ม. = กลับรถแล้ว ระบบสลับ "ขาไป/ขากลับ" ให้เอง

> ตัวอย่างจากภาพหน้าจอในคู่มือ: รถอยู่ห่างป้าย 5.2 กม. ตามถนน ÷ 30 กม./ชม. = 0.17 ชม. ≈ **10 นาที**

## 6. ออกแบบให้คนใช้เทคโนโลยีไม่เก่ง

- ตัวหนังสือใหญ่ ปุ่มใหญ่ (สูง 58–92 px) สีชัด เขียว = ใกล้ถึง เทา = ยังไม่มีรถ
- ผู้โดยสาร **ไม่ต้องสมัคร** ไม่ต้องใส่รหัส · กดครั้งเดียวหาป้ายใกล้ · จำป้ายไว้ เปิดครั้งหน้าเห็นเลย
- ปุ่ม 🔊 **อ่านออกเสียงภาษาไทย** สำหรับผู้สูงอายุ
- คนขับ: กดชื่อ + แป้นตัวเลขใหญ่ + ปุ่ม "เริ่มวิ่ง" ปุ่มเดียว · กันจอดับ · ปิดแอปแล้วเปิดใหม่แชร์ต่อเอง
- ผู้ดูแล: แตะแผนที่ปักป้าย ไม่ต้องรู้พิกัด · **บันทึกอัตโนมัติ** ไม่มีปุ่มบันทึกให้ลืม
- ส่งลิงก์ทาง **LINE** ได้ทุกหน้า (ช่องทางที่คนต่างจังหวัดใช้จริง)

## 7. ความปลอดภัย / ความเป็นส่วนตัว

- รหัสเก็บแบบเข้ารหัส (scrypt) ใครก็ดูรหัสเดิมไม่ได้ · ลองผิดเกิน 15 ครั้งล็อก 10 นาที
- ตำแหน่งผู้โดยสาร **ไม่ส่งออกจากมือถือ** · ตำแหน่งรถเก็บเฉพาะล่าสุด ไม่เก็บประวัติ กดหยุดแล้วลบ

## 8. ตัวเลขสำหรับคลิป

- โค้ดประมาณ **2,650 บรรทัด** (หน้าเว็บ 4 หน้า + API + ชุดทดสอบ)
- ชุดทดสอบอัตโนมัติ **54 ข้อ** ผ่านครบทั้งในเครื่องและบนเว็บจริง
- คู่มือมีรูปหน้าจอจริง **18 รูป**
- ค่าใช้จ่าย: **0 บาท** สำหรับหมู่บ้าน/ตำบลที่มีรถไม่กี่คัน (Vercel + Upstash แพ็กเกจฟรี)
- Pull Request บน GitHub 4 ครั้ง: สร้างแอป → แก้แผนที่ + QA → ชุดทดสอบ → คู่มือ

## 9. ข้อจำกัด (บอกตรง ๆ ในคลิป)

- คนขับต้อง **เปิดหน้าจอค้างไว้** (เว็บแอปส่ง GPS ตอนปิดจอไม่ได้) ถ้าอยากให้ส่งตอนปิดจอ ต้องทำแอป Android/iOS จริง
- เวลาเป็น **ค่าประมาณ** จากความเร็วเฉลี่ย ไม่รู้เรื่องรถติด/จอดแวะ
- ตำแหน่งบนหน้าผู้โดยสารช้ากว่าจริงประมาณ 10 วินาที (แลกกับประหยัดโควตาฟรี)
- ถ้ารถเยอะมาก/คนดูเยอะมาก อาจเกินแพ็กเกจฟรีของ Upstash

